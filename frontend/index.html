CodeVision o código por trás da imagem.

01

Propósito

Ensinar uma máquina a ler uma mensagem codificada do mesmo jeito que uma pessoa faria: olhando para a imagem, separando cada marca e decidindo se ela é um ponto ou um traço.

O CodeVision nasceu como projeto de Engenharia de Software para unir três áreas que raramente aparecem juntas em trabalhos de graduação: processamento digital de imagens, aprendizado de máquina e desenvolvimento web. O primeiro sistema de codificação suportado é o código Morse — simples o bastante para ser verificado à mão, rico o bastante para exigir decisões reais de engenharia.

O princípio que guia a arquitetura é a separação de responsabilidades: reconhecer o que há na imagem é um problema; interpretar o que isso significa é outro. Cada um vive no seu próprio módulo e pode ser testado de forma independente.

  • Ver

    Receber, validar e preparar a imagem enviada pelo usuário.

  • Reconhecer

    Localizar cada marca e classificá-la com uma rede neural.

  • Explicar

    Devolver posição, classe e confiança de cada símbolo — nada escondido.

02

Arquitetura

Um backend Django REST fino na borda, uma camada de serviços no meio e o módulo de IA isolado no fundo. Cada camada só conhece a de baixo.

  1. Borda HTTP

    views.py

    Recebe o multipart/form-data, aciona as validações, chama o serviço e traduz cada exceção de domínio em um status HTTP coerente.

    urls.py · views.py
  2. Contrato

    serializers.py + validators.py

    Validação em duas etapas: o serializer confere o campo imagem; os validadores reabrem o arquivo com Pillow para checar formato real, dimensões e integridade — sem confiar na extensão enviada.

    PNG · JPEG · WEBP · BMP · ≤ 10 MB · ≤ 10 000 px
  3. Serviço

    ServicoReconhecimento

    Carrega o modelo sob demanda, uma única vez por processo, protegido por threading.Lock. Corrige a orientação EXIF, converte para RGB, delega à IA e normaliza o resultado para o contrato da API.

    services.py · exceptions.py
  4. Inteligência

    Pacote ia/

    Independente do Django. Pré-processamento, segmentação, a CNN e o treinamento podem ser usados direto no terminal ou em um notebook.

    preprocessamento · reconhecimento · modelo · treinamento

Endpoints

MétodoRotaFunção
GET/api/health/Confirma que o backend está no ar.
GET/api/reconhecimento/status/Informa se o arquivo do modelo existe e se já está carregado em memória — sem carregá-lo.
POST/api/reconhecimento/Recebe o campo imagem e devolve os símbolos reconhecidos.

Como os erros chegam ao cliente

  • 400ErroValidacaoImagem, ErroProcessamentoImagem — arquivo inválido, corrompido, grande demais ou em formato não aceito.
  • 500ErroReconhecimento ou falha inesperada — registrada no log, nunca exposta em detalhe.
  • 503ModeloIAIndisponivel — os pesos ainda não foram treinados ou não puderam ser carregados.
03

Pipeline de IA

Da imagem bruta à lista de símbolos em quatro passos. Nenhum deles é mágico e é justamente isso que torna cada um testável.

  1. i.

    Pré-processamento

    A imagem vira escala de cinza. Se o brilho médio for menor que 127, ela é invertida para manter símbolos escuros sobre fundo claro. O contraste é reforçado em 1,5×.

    ia/preprocessamento.py — PreprocessadorCodeVision

  2. ii.

    Segmentação

    Limiarização de Otsu produz uma imagem binária; componentes conectados (vizinhança-8) isolam cada marca. Ruídos muito pequenos e manchas que ocupam a imagem inteira são descartados. A ordem de leitura é de cima para baixo, da esquerda para a direita.

    cv2.threshold · cv2.connectedComponentsWithStats

  3. iii.

    Normalização do recorte

    Cada componente é recortado com 2 px de margem, redimensionado para 32 × 32 com filtro Lanczos e convertido em um tensor (1, 32, 32) com valores entre 0 e 1.

  4. iv.

    Classificação

    A CNN devolve uma probabilidade para cada classe. Fundo é descartado; leituras abaixo de 60% de confiança são marcadas como baixa_confianca em vez de serem forçadas a virar símbolo.

    fundo0,02
    ponto0,95
    traço0,03

    ia/reconhecimento.py — ReconhecedorCodeVision

04

O modelo

Uma rede pequena de propósito: três blocos convolucionais e um classificador denso. Suficiente para distinguir um ponto de um traço, leve o bastante para rodar em CPU.

1 × 32 × 32entrada
16 × 16 × 16Conv 3×3 · BatchNorm · ReLU · MaxPool
32 × 8 × 8Conv 3×3 · BatchNorm · ReLU · MaxPool
64 × 4 × 4Conv 3×3 · BatchNorm · ReLU · MaxPool
128Linear · ReLU · Dropout 0,25
3fundo · ponto · traço

Treinamento

  • Dataset organizado em datasets/fundo, /ponto e /traco.
  • Divisão estratificada 80/20, com semente fixa (42) para reprodutibilidade.
  • Adam, taxa de aprendizado 0,001, weight decay 0,0001, entropia cruzada.
  • Avaliação com matriz de confusão, precisão, recall e F1 por classe.

Persistência

  • Pesos salvos em modelos/modelo_morse.pth.
  • Um .json ao lado guarda versão do formato, classes e tamanho de entrada.
  • Ao carregar, os metadados são conferidos antes dos pesos — modelos incompatíveis são recusados.
  • Leitura com weights_only=True, sem desserializar código arbitrário.
# terminal, a partir da raiz do projeto
python -m ia.treinamento

# ou, em Python
from ia.treinamento import TreinadorCodeVision
TreinadorCodeVision("datasets", "modelos").executar(epocas=20)
